# security-log-monitor 작업 기록 — 2026-03-14

## 1. 개요

Zeek NIDS를 홈서버 SIEM 스택에 통합했다.

```
네트워크 트래픽
    └─▶ Zeek (NIDS) → /opt/zeek/spool/logger/*.log (JSON)
                          └─▶ Promtail → Loki → Grafana
```

---

## 2. Zeek 설치

### 설치 경로

```
/opt/zeek/
├── bin/zeek, zeekctl
├── etc/zeekctl.cfg         # 클러스터 설정
│   └── node.cfg            # 인터페이스 지정
├── share/zeek/site/local.zeek  # 로드할 스크립트 목록
├── logs/                   # 로테이션된 아카이브
│   └── current -> /opt/zeek/spool/logger  (심볼릭 링크)
└── spool/logger/           # 실시간 로그 파일 (실제 경로)
```

### 실행 방식

Zeek는 `zeekctl` 클러스터 모드로 실행된다. 역할은 아래 4개다.

| 노드 | 역할 |
|------|------|
| logger | 로그 파일 기록 |
| manager | 클러스터 조율 |
| proxy-1 | 이벤트 중계 |
| worker-1 | 패킷 캡처 및 분석 |

## 3. Zeek 설정 — local.zeek 수정

파일: `/opt/zeek/share/zeek/site/local.zeek`

### 문제: 스크립트 충돌

`setup-zeek.sh`가 추가한 항목 일부가 Zeek 기본 설정과 중복되어 `deploy` 실패.

```
error: conflicting definition of enum value 'HTTP::SQL_Injection_Attacker'
error: conflicting definition of enum value 'HTTP::SQL_Injection_Victim'
```

원인: `detect-sqli.zeek`와 `detect-sql-injection.zeek`가 동일한 enum을 각각 정의.

### 해결: 중복 항목 주석 처리

| 제거 항목 | 이유 |
|-----------|------|
| `policy/protocols/http/detect-sqli` | `protocols/http/detect-sql-injection`이 기본 포함 |
| `policy/protocols/ssl/validate-certs` | 기본 설정에 이미 존재 |
| `policy/protocols/ssl/log-hostnames` | 기본 설정에 이미 존재 |
| `policy/protocols/dns/detect-external-names` | 기본 설정에 이미 존재 |
| `policy/misc/scan` | 이 Zeek 버전에 해당 스크립트 없음 |

### 최종 추가 항목 (SIEM 연동 섹션)

```zeek
@load policy/tuning/json-logs                    # JSON 포맷 출력 (Promtail 연동 필수)
@load policy/protocols/http/detect-webapps       # 웹 앱/프레임워크 핑거프린팅
@load policy/protocols/ssl/expiring-certs        # 만료 예정 인증서 → notice.log
@load policy/misc/detect-traceroute              # Traceroute 탐지 → notice.log
```

## 4. Zeek 실행 및 검증

```bash
sudo /opt/zeek/bin/zeekctl deploy
sudo /opt/zeek/bin/zeekctl status
```

정상 시 `spool/logger/`에 아래 로그 파일 생성:

```
conn.log       # TCP/UDP/ICMP 연결 (src/dst IP·port, proto, bytes, duration)
dns.log        # DNS 쿼리/응답

ssl.log        # TLS 핸드셰이크

weird.log      # 프로토콜 이상 행위
capture_loss.log
stats.log
```

## 5. Promtail 연동

### 핵심 문제: 심볼릭 링크

`/opt/zeek/logs/current`는 `/opt/zeek/spool/logger`를 가리키는 심볼릭 링크다.
Docker 컨테이너에 `/opt/zeek/logs`를 마운트하면 symlink 대상이 컨테이너 내부에 존재하지 않아 링크가 깨진다.

### 해결: spool/logger 직접 마운트

`docker-compose.yml` 변경:

```yaml
# 변경 전
- /opt/zeek/logs:/zeek-logs:ro

# 변경 후
- /opt/zeek/spool/logger:/zeek-logs/current:ro
```

실제 로그 디렉토리를 컨테이너 내부의 `/zeek-logs/current`로 직접 마운트.

### 파일 권한 문제

`/opt/zeek/spool/logger`는 `root:zeek (drwxrws---)` 권한이라 Promtail 컨테이너가 읽지 못한다.

해결:

```bash
sudo chmod o+rx /opt/zeek/spool /opt/zeek/spool/logger
sudo chmod o+r /opt/zeek/spool/logger/*
```

새로 생성되는 로그 파일에도 자동 적용되도록 cron 등록:

```
*/5 * * * * root chmod o+r /opt/zeek/spool/logger/* 2>/dev/null
```

파일: `/etc/cron.d/zeek-log-perms`

### Promtail 설정

파일: `config/promtail-config.yml`

추가된 scrape job 6개:

| job_name | 경로 | 주요 라벨 |
|----------|------|-----------|
| zeek_conn | `/zeek-logs/current/conn.log` | `proto`, `conn_state`, `service` |
| zeek_dns | `/zeek-logs/current/dns.log` | `qtype_name`, `rcode_name` |
| zeek_http | `/zeek-logs/current/http.log` | `method`, `status_code` |
| zeek_ssl | `/zeek-logs/current/ssl.log` | `version`, `validation_status` |
| zeek_notice | `/zeek-logs/current/notice.log` | `note` |
| zeek_weird | `/zeek-logs/current/weird.log` | `name` |

모든 job은 `pipeline_stages: json`으로 파싱. 고카디널리티 필드(IP 등)는 라벨이 아닌 로그 라인 내 JSON으로 유지하고, Grafana에서 `| json` 파이프로 조회.

## 6. 부팅 자동 시작

`zeekctl`은 systemd에 등록되지 않아 재부팅 시 수동 시작이 필요했다.

cron `@reboot`으로 해결:

```
@reboot root /opt/zeek/bin/zeekctl start
```

파일: `/etc/cron.d/zeek-log-perms` (권한 갱신 cron과 동일 파일에 추가)

최종 `/etc/cron.d/zeek-log-perms` 내용:

```
*/5 * * * * root chmod o+r /opt/zeek/spool/logger/* 2>/dev/null
@reboot root /opt/zeek/bin/zeekctl start
```

## 7. Grafana 대시보드

### zeek-dashboard.json

파일: `grafana/dashboards/zeek-dashboard.json`
대시보드명: **Zeek NIDS — 네트워크 행위 분석**
패널 수: 25개

| 섹션 | 패널 |
|------|------|
| 연결 분석 (conn.log) | 프로토콜별 연결 수, 총 연결 수, Top 출발지/목적지 IP, 연결 상태 분포, Zeek Notice |
| DNS 분석 (dns.log) | DNS 응답 코드 추이, Top 15 쿼리 도메인 |
| HTTP 분석 (http.log) | 메서드 분포, 상태코드 추이, Top Host, Top URI |
| SSL/TLS 분석 (ssl.log) | TLS 버전 분포, Top SNI, 인증서 검증 상태 |
| 보안 이벤트 (notice.log / weird.log) | Notice 유형별 추이, Weird 유형별 추이, 최근 Notice 원문, Top Weird, Notice 집계 |

## 9. zeekctl.cfg 추가 설정

파일: `/opt/zeek/etc/zeekctl.cfg`

```
umask 0022
```

신규 생성 파일의 기본 권한 완화 목적으로 추가.
단, zeekctl 자체가 umask를 반드시 따르지는 않으므로 cron 권한 갱신과 병행.
