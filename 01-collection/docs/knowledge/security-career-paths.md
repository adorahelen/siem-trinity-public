# 보안 3대 영역: 직업군 및 진입 경로 분석

> 작성일: 2026-03-10
> 참고: 성(城) 비유를 기반으로 각 보안 영역의 직업군·진입 난이도·현재 프로젝트와의 연결성 정리

---

## 프레임워크 요약

보안은 크게 세 영역으로 나뉜다. 단순한 기술력보다 **성향에 따른 핏(Fit)**이 직업 선택에 결정적이다.

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│  성 밖             성 자체              성 안                    │
│  Offensive         Engineering          IR / Governance          │
│                                                                 │
│  공격, 탐색         구축, 운영           분석, 전략               │
│  진입: 상(High)     진입: 중(Medium)     진입: 중상(Med-High)     │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

---

## 1. 성 밖: 취약점을 찾아 뚫어보는 쪽 (Offensive Security)

해커의 관점으로 시스템의 허점을 먼저 찾아내는 **공격형** 보안.

### 주요 직업군

| 직무 | 설명 |
|------|------|
| 모의해킹 전문가 (Penetration Tester) | 기업의 승인을 받아 합법적으로 침투 후 취약점 보고서 작성 |
| 취약점 분석가 (Vulnerability Researcher) | 소프트웨어·하드웨어 코드를 분석해 제로데이(0-day) 취약점 발굴 |
| 레드팀 (Red Teamer) | 기술 침투뿐 아니라 물리적 침투·사회공학까지 포함한 전방위 공격 시뮬레이션 |
| 버그 바운티 헌터 | 기업의 버그 바운티 프로그램에 참여해 취약점 신고 후 포상금 수령 |

### 진입 난이도: 상 (High)

도구 사용법을 아는 것을 넘어, **프로그래밍 + 네트워크 + OS 내부 구조**에 대한 깊은 이해가 필수.
막혔을 때 우회 방법을 창의적으로 찾는 문제 해결 능력이 없으면 실무에서 한계가 생긴다.

### 접근 방법

- CTF(Capture The Flag) 해킹 방어 대회 참여
- 버그 바운티 활동 (HackerOne, Bugcrowd)
- OSCP (Offensive Security Certified Professional) 자격증
- 독립적인 취약점 연구 및 PoC(개념 증명) 작성

### 이 프로젝트와의 연결성

```
직접 연결: ❌
간접 연결: 🟡 중간

공격 기법(SQLi, LFI, XSS)을 이해하면
ModSecurity CRS 룰을 읽고 커스텀 룰을 작성할 때 직접 도움이 된다.

"어떻게 공격하는가" → "어떤 패턴을 막아야 하는가"
```

## 2. 성 자체: 견고하게 구축하고 운영하는 쪽 (Security Engineering & Ops)

성벽을 설계하고, CCTV를 달고, 출입문을 통제하는 **방어형** 보안.

### 주요 직업군

| 직무 | 설명 |
|------|------|
| 보안 솔루션 엔지니어 | 방화벽·WAF·IDS/IPS 등 보안 장비를 고객사에 설치·설정·기술 지원 |
| 보안 운영자 (SecOps) | 사내 보안 시스템이 24시간 정상 동작하도록 관리 및 설정 최적화 |
| 보안 관제 (SOC Analyst) | 실시간 모니터링으로 외부 공격 징후를 포착하고 1차 대응 |
| 클라우드 보안 엔지니어 | AWS·Azure·GCP 환경에서 IAM, 네트워크 보안, 컴플라이언스 설정 |
| 보안 아키텍트 | 전체 보안 구조를 설계하는 역할 — "이 성은 어디에, 어떻게 지을 것인가" |
| DevSecOps 엔지니어 | 개발 파이프라인(CI/CD)에 보안 자동화를 통합 |

### 진입 난이도: 중 (Medium)

신입이 가장 많이 진입하는 **보안 관제(SOC)**가 이 영역에 해당.
인프라 전반(서버, 네트워크, 리눅스)에 대한 실무 지식이 핵심.
꼼꼼하고 안정 지향적인 성향이 장기적으로 유리하다.

### 접근 방법

- 리눅스 서버 실무 학습 (이 프로젝트가 직접 해당)
- 네트워크 관리사, 정보보안기사 자격증
- SIEM·로그 분석 실습 경험 (이 프로젝트가 직접 해당)
- 클라우드 보안 자격증 (AWS Security Specialty 등)

### 이 프로젝트와의 연결성

```
직접 연결: ✅ 높음

이 프로젝트 전체가 "성 자체" 영역에 해당한다.

구현한 것:
  UFW (방화벽) + Fail2Ban (IPS)
  Promtail → Loki → Grafana (SIEM 파이프라인)
  로그 파싱, 대시보드, 알림 설정 (진행 중)

구현 예정:
  ModSecurity (WAF) — 성문 검문소 추가
  Wazuh (HIDS) — 내부 감시 카메라 추가
```

## 3. 성 안: 실마리를 찾고 전략을 짜는 쪽 (Incident Response & Governance)

사고가 터진 후 범인을 추적하거나, 사고가 나지 않도록 법규를 만드는 **두뇌형** 보안.

### 주요 직업군

| 직무 | 설명 |
|------|------|
| 침해사고 대응 (CERT/CSIRT/IR) | 사고 발생 시 즉시 투입, 피해 최소화·경로 차단·원인 분석 |
| 디지털 포렌식 전문가 (DFIR) | 삭제된 데이터·로그 복구, 법적 증거 수집 |
| 보안 컨설턴트 (ISMS-P / 개인정보) | 기업의 법적 컴플라이언스 충족 여부 점검 및 가이드라인 제시 |
| 보안 기획 / 거버넌스 (GRC) | 조직 전체 보안 프로세스·정책·예산 설계 |
| 위협 인텔리전스 분석가 | 공격 그룹 TTP(전술·기술·절차)를 추적하고 선제적 방어 전략 수립 |

### 진입 난이도: 중상 (Medium-High)

사고 대응은 높은 기술적 숙련도가 요구되며,
컨설팅·기획은 기술 외에 **법률 지식 + 문서 작성 능력 + 소통 능력**이 필수.
단독으로 진입하기보다 "성 자체" 운영 경험을 쌓은 후 전환하는 경로가 일반적이다.

### 접근 방법

- 정보보안기사, CISA, CISSP 자격증
- 디지털 포렌식 전문가 자격증
- SIEM 운영 경험 후 이벤트 분석 역량 확장
- 보안 규정(개인정보 보호법, ISMS-P 기준) 학습

### 이 프로젝트와의 연결성

```
직접 연결: △ 부분적

Loki에 로그가 축적되므로 사후 타임라인 재구성은 가능.
Grafana로 공격 시도 패턴 분석 가능.

그러나 현재 한계:
  "공격자가 성 안에서 무엇을 했는가"는 추적 불가
  파일 변조·권한 상승·백도어 설치 등 내부 행동은 Wazuh 없이 탐지 불가

Wazuh 도입 후:
  MITRE ATT&CK 전술 매핑 → 이벤트 해석 능력 → IR 역량으로 연결
```

## 4. 직업군 비교 요약

| 구분 | 성격 | 대표 직무 | 진입 장벽 | 핵심 성향 |
|------|------|---------|---------|---------|
| 성 밖 (Offensive) | 공격형 | 모의해킹, 레드팀 | 매우 높음 | 호기심, 집요함, 창의적 파괴 |
| 성 자체 (Engineering) | 구축·운영형 | 엔지니어, SOC, SecOps | 보통 | 꼼꼼함, 안정 지향, 인프라 친화 |
| 성 안 (IR/Governance) | 분석·전략형 | CERT, 포렌식, 컨설팅 | 높음 | 논리적 추론, 소통 능력, 법규 이해 |

**취업 문턱이 가장 낮은 영역:** 성 자체 → 신입 보안 관제(SOC)

**대우가 가장 좋은 영역:** 성 밖 → 수준 높은 모의해킹·레드팀, 취약점 연구

**경력 전환이 유리한 경로:** 성 자체 경험 → 성 안(IR/컨설팅)으로 이동

## 5. 이 프로젝트의 커리어 포지셔닝

```
현재 이 프로젝트가 증명하는 역량:

  [운영 체계 설계]
    Docker 기반 SIEM 인프라 구성 (Loki + Grafana + Promtail)

  [로그 수집 및 파싱]
    Promtail pipeline_stages로 auth.log, ufw.log, nginx, fail2ban 파싱
    Python exporter로 명령 출력(ss, lastb, tailscale) 수집

  [보안 모니터링]
    UFW + Fail2Ban 운영 및 로그 연동
    Grafana 대시보드 8개 패널 구성

  → "보안 엔지니어링 / SOC / 보안 운영" 직무에 직접 연결되는 포트폴리오

향후 이 프로젝트가 증명할 역량:

  [WAF 운영]   ModSecurity 도입 → 보안 솔루션 엔지니어 역량
  [HIDS 운영]  Wazuh 도입 → HIDS 운영 + MITRE ATT&CK 해석 → IR 방향으로 확장
  [검증 실습]  CALDERA → "공격 시뮬레이션 → 탐지 룰 보강" → 레드팀 지식 간접 습득
```

## 6. 커리큘럼과 커리어 영역 매핑

| 커리큘럼 | 해당 영역 | 현재 프로젝트 기여 |
|---------|---------|----------------|
| Snort IDS/IPS | 성 자체 (네트워크 레이어) | 🔶 낮음 — 아키텍처 불일치 |
| Post Exploitation + 웹 보안 | 성 밖 (공격자 기법 학습) | 🟡 중간 — ModSecurity 룰 작성 시 활용 |
| OPNSense (방화벽) | 성 자체 | 🔶 낮음 — UFW로 이미 커버 |
| ModSecurity (WAF) | 성 자체 | ✅ 높음 — FuturePlan 5순위 직접 연결 |
| Wazuh XDR | 성 자체~성 안 경계 | ✅ 높음 — FuturePlan 6순위 직접 연결 |
| MITRE ATT&CK | 3영역 모두 연결 | 🟡 중간 — Wazuh 도입 후 필수 선행 지식 |
| CALDERA (BAS) | 성 밖 → 성 자체 검증 | 🟡 중간 — Wazuh 설치 후 탐지 룰 검증 용도 |
