# 보안 특화 LLM — SecLM과 사이버보안 AI

> 작성일: 2026-03-20
> 일반 LLM과 다른 보안 도메인 특화 모델들

---

## 왜 보안 특화 LLM이 필요한가

```
일반 LLM의 한계:
  CVE-2024-XXXXX 최신 취약점 모름 (학습 데이터 시점 제한)
  MITRE ATT&CK 전술/기술 체계 이해 부족
  Suricata 시그니처 문법 이해 미흡
  악성코드 분석에 특화된 언어 패턴 부족

보안 특화 모델:
  보안 관련 문서, CVE, 취약점 보고서, 악성코드 분석 보고서로 파인튜닝
  → 보안 용어, 공격 패턴, 대응 절차에 강함
```

## 주요 보안 특화 모델

### SecLM (Google DeepMind)

```
공개 여부: 일부 공개 (API 형태)
특징:
  - 악성코드 분석, 취약점 설명에 특화
  - Mandiant 위협 인텔리전스 데이터로 학습
  - Google VirusTotal 통합

강점:
  - 악성코드 바이너리 설명
  - 공격 캠페인 연관 분석
  - IOC (침해 지표) 추출
```

### CyberSecEval (Meta)

```
모델이 아닌 벤치마크 (평가 기준)
llama 계열이 보안 지식을 얼마나 갖추었는지 측정

평가 항목:
  - 취약한 코드 탐지
  - 사이버 공격 지식 (공격/방어 양면)
  - 안전한 코드 생성
  - 프롬프트 인젝션 저항성

의의:
  어떤 LLM이 보안 도메인에 더 적합한지 비교 가능
```

### Llama Guard (Meta)

```
모델이 아닌 안전 필터
LLM 입출력에서 유해 콘텐츠 감지

보안 관련 활용:
  - 프롬프트 인젝션 감지
  - 악성 명령 실행 방지
  - 민감 정보 유출 방지
```

### 기타 보안 특화 시도들

```
WizardCoder + 보안 파인튜닝:
  취약점 코드 탐지, 패치 제안

HackerGPT (비공식):
  버그 바운티, 침투 테스트 특화
  윤리적 해킹 지원

SecurityBERT:
  네트워크 트래픽 분류
  전통 ML 파이프라인에 임베딩 모델로 활용
```

## 벤치마크 — 보안 LLM 성능 평가

```
CTF (Capture The Flag) 벤치마크:
  실제 CTF 문제를 LLM이 풀 수 있는가
  GPT-4o: 일부 Low~Medium 난이도 해결
  o3: 고난이도 문제도 일부 해결

취약점 탐지 벤치마크:
  CWE 분류 기반 코드 취약점 탐지
  일반 LLM vs 보안 특화 LLM 비교

CVE 이해도:
  CVE 설명 → 공격 벡터 / 영향도 / 패치 방법 설명 정확성
```

## 이 프로젝트에서 보안 특화 모델 활용 방안

```
현재:
  llama3.1:8b (일반 모델) + RAG (보안 로그 컨텍스트)
  → RAG가 보안 특화 역할을 일부 보완

업그레이드 시나리오:

방안 1 — 보안 특화 모델로 교체:
  .env에서 OLLAMA_MODEL=보안특화모델명 변경
  단, 로컬 실행 가능한 보안 특화 모델이 현재 제한적

방안 2 — 일반 모델 + 보안 프롬프트 최적화:
  현재 방식 유지
  시스템 프롬프트에 MITRE ATT&CK 체계 명시

방안 3 — 하이브리드:
  일반 질의: llama3.1:8b 로컬 (빠름, 무료)
  복잡한 위협 분석: SecLM API 또는 Claude (정확, 유료)
```

## MITRE ATT&CK — 보안 LLM의 공통 언어

```
보안 도메인의 표준 공격 분류 체계
보안 특화 LLM은 이 체계를 기반으로 학습

구조:
  전술 (Tactic) → 기술 (Technique) → 서브기술
  "무엇을 하려는가" → "어떻게"

예시:
  전술: Initial Access (최초 접근)
  기술: T1190 - Exploit Public-Facing Application
  서브기술: T1190.001 - ...

이 프로젝트 로그와 연결:
  Suricata alert → 해당 ATT&CK 기술 매핑 가능
  → 프롬프트에 ATT&CK 맥락 추가 시 분석 품질 향상
```
