# sLLM 정의 및 이 프로젝트 적용 현황

> 작성일: 2026-03-19
> 관련 프로젝트: XDR RAG — 보안 로그 분석 시스템

---

## sLLM이란?

**sLLM (small Large Language Model)** — 소형 언어 모델

일반적으로 **~13B 파라미터 이하**의 언어 모델을 지칭합니다.
"small"이지만 여전히 수십억 개의 파라미터를 가진 강력한 모델입니다.

### 대형 LLM과의 비교

| 구분 | 모델 예시 | 파라미터 | 실행 환경 |
|------|---------|---------|---------|
| **sLLM** | llama3.1:8b | 8B | 개인 노트북 |
| **sLLM** | qwen2.5:14b | 14B | 개인 노트북 |
| 대형 LLM | GPT-4 | ~1.8T (추정) | 클라우드 전용 |
| 대형 LLM | Claude Sonnet/Opus | 수백B (비공개) | 클라우드 전용 |
| 대형 LLM | Llama 3.1 405B | 405B | A100 서버급 |

---

## 이 프로젝트의 분류

```
sLLM (llama3.1:8b)
  + RAG (Loki 로그 → ChromaDB → 검색 증강)
  + Domain-specific (보안 로그 도메인 특화)
= "도메인 특화 sLLM RAG 시스템"
```

## 실제 사용 현황

### 현재 사용 모델

| 역할 | 모델 | 파라미터 | 비고 |
|------|------|---------|------|
| 답변 생성 (LLM) | `llama3.1:8b` | 8B | 메인 추론 모델 |
| 텍스트 벡터화 (임베딩) | `nomic-embed-text` | 137M | 로그 → 벡터 변환 전용 |

### 모델이 처리하는 작업

```
llama3.1:8b 가 하는 일:
  - 보안 로그 컨텍스트를 읽고 한국어로 분석 답변 생성
  - 위험도 판단 [낮음 / 중간 / 높음 / 심각]
  - 권고 조치 제안
  - 일간/주간 보안 보고서 문장 생성

nomic-embed-text 가 하는 일:
  - Loki에서 가져온 로그 텍스트 → 숫자 벡터로 변환
  - 질문과 유사한 로그를 ChromaDB에서 찾을 때 사용
  - 답변 생성에는 관여하지 않음
```

## sLLM + RAG 조합을 선택한 이유

### 문제: 8B 모델 단독으로는 한계가 있음

```
사용자: "어제 밤 공격자 IP는?"

llama3.1:8b 단독:
  → "죄송합니다. 저는 실시간 서버 정보를 알 수 없습니다."
  (학습 데이터에 우리 서버 로그가 없기 때문)
```

### 해결: RAG로 실시간 로그를 컨텍스트에 주입

```
사용자: "어제 밤 공격자 IP는?"

RAG 시스템:
  1. 질문을 벡터로 변환 (nomic-embed-text)
  2. ChromaDB에서 관련 로그 검색
     → "2026-03-19 02:13 auth Invalid user admin from 218.92.0.23"
  3. 검색된 로그 + 질문을 llama3.1:8b에 전달
  4. llama3.1:8b: "218.92.0.23에서 새벽 2시에 admin 계정 공격 시도가 있었습니다. 위험도: 높음"
```

### Fine-tuning 대신 RAG를 선택한 이유

| 방법 | 비용 | 최신 데이터 반영 | 선택 |
|------|------|----------------|------|
| Fine-tuning | GPU 수백 시간 + 재학습 | 재학습 필요 | ❌ |
| RAG | 로그 동기화만 (분 단위) | 실시간 가능 | ✅ |

> Fine-tuning 없이 도메인 지식을 주입할 수 있다는 것이 RAG의 핵심 가치입니다.
