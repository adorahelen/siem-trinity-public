# RAG 고급 패턴

> 작성일: 2026-03-19
> 현재 이 프로젝트: 기본 RAG / 향후 적용 가능한 고급 패턴

---

## 기본 RAG (현재 이 프로젝트)

```
질문 → 벡터 검색 → 컨텍스트 주입 → LLM → 답변
```

단순하고 안정적이나, 검색 품질이 낮으면 답변도 나빠지는 한계.

---

## 고급 RAG 패턴

### ① HyDE (Hypothetical Document Embedding)

```
문제: 질문과 로그의 표현 방식이 달라서 검색이 안 맞음
  질문: "SSH 공격 심했어?"
  로그: "Invalid user admin from 218.92.0.23"
  → 의미는 같지만 벡터가 멀 수 있음

해결: LLM이 먼저 "가상의 답변"을 생성 → 그것으로 검색
  1. 질문 → LLM → "최근 SSH 공격이 18건 탐지되었고 IP는..." (가상 답변)
  2. 가상 답변 벡터로 ChromaDB 검색 → 실제 로그와 더 잘 매칭
  3. 실제 로그 + 질문 → LLM → 최종 답변
```

---

### ② Self-RAG

```
문제: 검색 결과가 항상 필요한 건 아님 ("안녕"에도 검색을 함)

해결: LLM이 스스로 판단
  1. 질문을 보고 "검색이 필요한가?" 판단
  2. 필요하면 검색 → 검색 결과 품질도 자체 평가
  3. 불필요하면 바로 답변
  4. 답변 후 "이 답변이 근거가 있는가?" 자체 검증
```

---

### ③ Corrective RAG (CRAG)

```
문제: 검색 결과가 질문과 무관한 경우 그대로 사용

해결: 검색 결과를 평가하고 부족하면 보완
  1. 검색 실행
  2. 검색 결과 평가: "이게 질문과 관련 있는가?"
     - 관련 있음 → 그대로 사용
     - 관련 없음 → 웹 검색 or 다른 소스로 보완
     - 애매함   → 관련 부분만 추출해서 사용
```

---

### ④ Agentic RAG (2024~)

```
문제: 단순 검색으로 답할 수 없는 복잡한 질문
  "지난 주와 이번 주 공격 패턴을 비교해줘"
  → 두 번의 검색 + 비교 분석 필요

해결: Agent가 RAG를 여러 번 반복 실행
  1. "지난 주 공격 로그 검색" → 결과1
  2. "이번 주 공격 로그 검색" → 결과2
  3. 결과1 + 결과2 비교 분석 → 최종 답변
```

---

### ⑤ Graph RAG (Microsoft, 2024)

```
문제: 단순 벡터 검색은 문서 간 관계를 파악 못함
  "A 공격자가 B 서비스를 공격했고 C IP를 사용했다"
  → 벡터로는 A-B-C 관계 파악 어려움

해결: 지식 그래프(Knowledge Graph) + 벡터 DB 병행
  공격자 IP → 공격 대상 → 사용 포트 → 시간대
  그래프 구조로 관계를 저장하고 탐색

적용 예:
  "이 IP가 과거에도 같은 패턴을 보였나?"
  → 그래프에서 IP 노드의 히스토리 탐색
```

## 이 프로젝트 적용 우선순위

| 패턴 | 효과 | 난이도 | 추천 시기 |
|------|------|--------|---------|
| **HyDE** | 검색 정확도 향상 | ⭐⭐ | 단기 |
| **Self-RAG** | 불필요한 검색 제거, 속도↑ | ⭐⭐⭐ | 중기 |
| **Agentic RAG** | 복잡한 질문 처리 | ⭐⭐⭐⭐ | Agent 도입 후 |
| **CRAG** | 검색 품질 보증 | ⭐⭐⭐ | 중기 |
| **Graph RAG** | 공격자 관계 분석 | ⭐⭐⭐⭐⭐ | 장기 |
