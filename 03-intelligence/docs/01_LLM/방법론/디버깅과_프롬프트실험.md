# 디버깅과 프롬프트 실험 — LLM 품질 개선 실전 가이드

> 작성일: 2026-03-20
> 모델 답변이 이상할 때 원인 찾기 + 프롬프트 반복 실험

---

## LLM 답변 품질 문제 유형

```
① 엉뚱한 답변  — 질문과 무관한 내용 출력
② 환각         — 없는 사실을 있는 것처럼 답변
③ 형식 불일치  — 지시한 형식(위험도 명시 등)을 따르지 않음
④ 언어 혼용    — 한국어 지시했는데 영어 섞임
⑤ 과도한 분석  — "안녕"에 보안 보고서 출력
⑥ 너무 짧음    — 구체적 수치 없이 두루뭉술 답변
```

---

## 디버깅 순서

### 1단계 — RAG 문제인가, LLM 문제인가

```
먼저 검색된 컨텍스트를 직접 확인

# rag_chain.py의 retriever 단독 테스트
docs = retriever.invoke("SSH 공격 IP")
for doc in docs:
    print(doc.page_content[:200])

확인 항목:
  - 관련 로그가 검색됐는가?
  - 검색된 로그가 질문과 실제로 관련 있는가?
  - 로그가 너무 오래됐거나 비어있지 않은가?

컨텍스트가 나쁘면 → embedder.py, 동기화 문제
컨텍스트가 좋은데 답변이 나쁘면 → 프롬프트 문제
```

### 2단계 — 실시간 컨텍스트 확인

```
rag_chain.py의 _fetch_realtime_context() 단독 실행
→ Loki 쿼리가 정상 반환하는지 확인

빈 문자열 반환 시:
  Loki 연결 상태 확인 (curl http://100.x.x.x:3100/ready)
  해당 시간대에 로그가 없을 수 있음
```

### 3단계 — 프롬프트 단독 테스트

```python
# LLM에 직접 프롬프트 보내기 (RAG 없이)
from langchain_ollama import ChatOllama
llm = ChatOllama(model="llama3.1:8b", temperature=0.1)
response = llm.invoke("여기에 테스트 프롬프트")
print(response.content)

→ 모델 자체 동작 격리 확인
```

## 프롬프트 실험 방법론

### A/B 테스트 원칙

```
한 번에 하나만 바꾼다

나쁜 예:
  시스템 프롬프트 변경 + Temperature 변경 + 예시 추가 동시
  → 어떤 변경이 효과가 있는지 모름

좋은 예:
  1회차: 시스템 프롬프트만 수정 → 결과 기록
  2회차: Temperature만 수정 → 결과 기록
  3회차: 예시 추가 → 결과 기록
  → 각 변경의 효과를 분리해서 파악
```

### 반복 실험 기록 양식

```
테스트 케이스: "어제 SSH 공격 현황 알려줘"
날짜: 2026-03-20

변경 내용: 시스템 프롬프트에 "IP별 건수 표 형식으로" 추가

이전 출력:
  "어제 여러 IP에서 SSH 공격이 있었습니다..."

이후 출력:
  "| IP | 건수 | 시간대 |
   |218.92.0.23 | 127건 | 02:00~03:00 |"

평가: ✅ 개선됨 (구체적 수치, 표 형식)
```

## 자주 효과적인 프롬프트 기법

### 형식 강제

```
나쁨: "위험도를 포함해서 답변해"
좋음: "반드시 다음 형식으로 답변: 위험도: [낮음/중간/높음/심각]"
```

### 부정 지시

```
"데이터가 없으면 추측하지 말고 '확인되지 않습니다'라고 답변"
"존재하지 않는 IP나 이벤트를 만들어내지 말 것"
```

### 역할 구체화

```
나쁨: "보안 전문가처럼 답변해"
좋음: "당신은 Suricata, Zeek, Wazuh 로그를 분석하는
      SOC 분석가입니다. 한국어로 답변하고,
      위험도와 권고 조치를 반드시 포함합니다."
```

### 출력 길이 제어

```
너무 짧을 때: "구체적인 IP 주소, 건수, 시간대를 포함해 상세히 설명"
너무 길 때:   "3문장 이내로 핵심만 요약"
```

## 이 프로젝트에서 발견된 실제 문제와 해결

| 문제 | 원인 | 해결 |
|------|------|------|
| "안녕"에 보안 보고서 출력 | 시스템 프롬프트가 모든 입력을 보안 분석 강제 | 대화/분석 모드 구분 추가 |
| 실시간 데이터가 질문에 섞임 | realtime 컨텍스트를 question에 합쳐서 전달 | dict로 분리 (`realtime` 별도 필드) |
| 영어로 답변 | 한국어 지시 약함 | "반드시 한국어로" 강화 |
| 없는 IP 날조 | 컨텍스트 없을 때 환각 | "데이터 없으면 명시" 지시 추가 |

## 품질 평가 기준

```
체크리스트 (매 실험 후 평가):

□ 질문에 실제로 답했는가?
□ 구체적 수치(IP, 건수, 시간)가 포함됐는가?
□ 위험도가 명시됐는가?
□ 권고 조치가 실행 가능한가?
□ 한국어로만 답변했는가?
□ 데이터가 없는 부분을 명확히 표시했는가?
□ 없는 정보를 지어내지 않았는가?
```
