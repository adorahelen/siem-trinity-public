# 임베딩 (Embedding)

> 작성일: 2026-03-19
> 관련 파일: `embedder.py`, `rag_chain.py` — `nomic-embed-text`

---

## 임베딩이란?

텍스트를 **숫자 벡터(배열)**로 변환하는 것.
"의미가 비슷한 텍스트는 비슷한 숫자 벡터"가 되도록 학습된 모델이 변환.

```
"SSH 공격 탐지" → [0.23, -0.87, 0.45, 0.12, ..., 0.67]  (768개 숫자)
"SSH brute force" → [0.21, -0.85, 0.48, 0.10, ..., 0.65] ← 비슷한 숫자
"오늘 점심 뭐 먹지" → [-0.92, 0.34, -0.71, ..., -0.23]  ← 다른 숫자
```

---

## 왜 숫자로 바꾸는가?

컴퓨터는 텍스트의 "의미"를 직접 비교할 수 없습니다.
숫자 벡터로 바꾸면 **수학적으로 의미 유사도를 계산**할 수 있습니다.

```
유사도 계산: Cosine Similarity
  두 벡터가 가리키는 방향이 비슷할수록 → 의미가 비슷

"SSH 공격" 벡터 vs "brute force" 벡터 → 각도 작음 → 유사도 높음
"SSH 공격" 벡터 vs "점심 메뉴" 벡터  → 각도 큼   → 유사도 낮음
```

---

## 이 프로젝트의 임베딩 흐름

```
[로그 저장 시]
로그 텍스트 (20줄)
    │
    ▼ nomic-embed-text (Ollama)
[0.23, -0.87, 0.45, ..., 0.67]  (768차원 벡터)
    │
    ▼
ChromaDB에 {텍스트 + 벡터} 함께 저장

[검색 시]
사용자 질문: "SSH 공격 IP 알려줘"
    │
    ▼ nomic-embed-text (동일 모델로 변환!)
[0.19, -0.82, 0.51, ..., 0.71]  (질문 벡터)
    │
    ▼ ChromaDB에서 유사한 벡터 검색
가장 가까운 벡터의 원본 로그 텍스트 반환
```

**핵심:** 저장할 때와 검색할 때 **반드시 같은 임베딩 모델** 사용해야 함.
다른 모델로 바꾸면 ChromaDB 전체 재구축 필요.

## nomic-embed-text 특징

```
크기:   274MB (매우 가벼움)
차원:   768차원 벡터
특징:   영어/다국어 지원, 보안 로그 같은 기술적 텍스트에 강함
속도:   로컬 Ollama에서 매우 빠름 (LLM과 달리 추론 불필요)
```

## 임베딩 모델 종류 비교

| 모델 | 차원 | 특징 |
|------|------|------|
| `nomic-embed-text` | 768 | 현재 사용, 경량, 빠름 |
| `mxbai-embed-large` | 1024 | 더 정확, 더 무거움 |
| OpenAI `text-embedding-3-small` | 1536 | 클라우드, 유료 |
| OpenAI `text-embedding-3-large` | 3072 | 최고 품질, 유료 |

차원이 높을수록 더 세밀한 의미 구분 가능 — 대신 저장 공간, 검색 속도 증가.
