# Hallucination (환각) — LLM의 거짓말

> 작성일: 2026-03-19
> 관련 파일: `rag_chain.py` — RAG가 환각을 줄이는 핵심 이유

---

## Hallucination이란?

LLM이 **사실과 다른 내용을 자신 있게 답변**하는 현상.

```
질문: "어제 밤 우리 서버를 공격한 IP는?"

LLM 단독 (RAG 없음):
  → "192.168.1.100에서 공격이 있었습니다." (완전히 지어낸 IP)
  → 틀렸지만 자신 있게 답함
  → 사용자는 사실인지 구분 불가
```

---

## 왜 발생하는가?

LLM은 학습 데이터의 **패턴**을 학습합니다.
"그럴듯한 다음 단어"를 예측하는 구조이기 때문에,
모르는 내용도 패턴에 맞게 생성해버립니다.

```
학습 데이터에 없는 정보 → 비슷한 패턴으로 생성 → 그럴듯한 거짓말
```

---

## RAG가 환각을 줄이는 원리

```
RAG 없음:
  질문 → LLM의 기억(학습 데이터)에서 생성 → 환각 위험

RAG 있음:
  질문 → 실제 로그 검색 → [검색된 로그 + 질문] → LLM → 근거 기반 답변
```

시스템 프롬프트에도 명시:
```
"컨텍스트에 없는 내용은 '해당 데이터가 확인되지 않습니다'라고 명시"
```

---

## 환각의 종류

| 종류 | 설명 | 예시 |
|------|------|------|
| **사실 환각** | 없는 사실을 만들어냄 | 없는 IP, 없는 이벤트 |
| **날짜 환각** | 날짜/시간 오류 | "어제"를 다른 날짜로 |
| **수치 환각** | 숫자를 지어냄 | 공격 건수 임의 생성 |
| **출처 환각** | 없는 논문/링크 생성 | 가짜 URL 제시 |

---

## 이 프로젝트에서 환각 최소화 방법

```
1. RAG       → 실제 로그를 컨텍스트로 제공
2. Prompt    → "컨텍스트에 없으면 모른다고 해"
3. Temperature=0.1 → 창의적 생성 억제 (낮을수록 보수적)
4. 출처 포함 → 검색된 로그 청크를 함께 표시 (향후 개선 가능)
```

---

## 환각이 완전히 없어지지는 않는다

RAG를 써도 환각은 0%가 되지 않습니다.

```
환각이 남는 경우:
- 검색 결과 자체가 불완전할 때
- 컨텍스트가 너무 길어 LLM이 일부를 무시할 때
- LLM이 검색 결과를 잘못 해석할 때
```

보안 분석에서는 **답변의 근거(로그 원문)를 항상 확인**하는 습관이 중요합니다.
