## 원리

```
현재 (invoke):
  chain.invoke(...)
  → LLM이 전체 답변 생성 완료 후 한 번에 반환
  → 사용자는 수 초간 빈 화면 대기

스트리밍 (stream):
  chain.stream(...)
  → LLM이 토큰 생성할 때마다 조각(chunk)을 즉시 yield
  → 사용자는 첫 단어부터 실시간으로 확인 (ChatGPT 같은 UX)
```

---

## LangChain LCEL 지원 여부

LangChain LCEL 파이프라인은 **추가 설정 없이 `.stream()` 지원**.
현재 `rag_chain.py`의 체인 구조 변경 불필요, **호출부만 수정**.

```python
# 현재 (invoke)
result = chain.invoke({"question": question, "realtime": realtime})

# 스트리밍 (stream)
for chunk in chain.stream({"question": question, "realtime": realtime}):
    print(chunk, end="", flush=True)
```

## 변경 범위

### rag_chain.py — query_stream() 추가

기존 `query()` 함수는 유지, 스트리밍 전용 함수를 별도로 추가.

```python
def query_stream(question: str, context_hours: int = 24):
    """스트리밍 응답 제너레이터 — 토큰 단위로 yield"""
    global _chain
    if _chain is None:
        build_chain()

    realtime = None
    if any(kw in question for kw in ["공격", "SSH", "차단", "Suricata", "Wazuh"]):
        try:
            realtime = _fetch_realtime_context(context_hours)
        except Exception:
            pass

    for chunk in _chain.stream({
        "question": question,
        "realtime": realtime or "현재 조회된 실시간 데이터 없음",
    }):
        yield chunk
```

### cli.py — stream 출력

```python
# 기존
with console.status("[bold green]분석 중...[/bold green]", spinner="dots"):
    answer = rag_chain.query(question)
console.print(Panel(answer, ...))

# 스트리밍으로 교체
console.print("[bold green]분석 결과[/bold green]")
answer_parts = []
for chunk in rag_chain.query_stream(question):
    print(chunk, end="", flush=True)
    answer_parts.append(chunk)
print()  # 줄바꿈
answer = "".join(answer_parts)
```

---

### app.py — st.write_stream()

Streamlit 1.28+ 에서 `st.write_stream()` 지원.

```python
# 기존
with st.spinner("분석 중..."):
    answer = rag_chain.query(question)
st.markdown(answer)

# 스트리밍으로 교체
answer = st.write_stream(rag_chain.query_stream(question))
```

`st.write_stream()` 은 제너레이터를 받아 자동으로 실시간 출력.

## 주의사항

```
Ollama 스트리밍:
  - Ollama는 기본적으로 스트리밍 지원
  - langchain-ollama 라이브러리가 이를 자동 처리
  - 별도 Ollama 설정 변경 불필요

Retriever 단계:
  - ChromaDB 검색은 스트리밍 불가 (검색 완료 후 LLM 전달)
  - 실제 스트리밍은 LLM 답변 생성 단계에서만 발생
  - 즉, 검색 시간(~1초)은 그대로, 답변 출력만 실시간으로 변경
```

---

## 기대 효과

```
이전: [검색 1초] + [LLM 생성 5초] + [출력] = 6초 후 전체 출력
이후: [검색 1초] + [즉시 출력 시작] = 1초 후 첫 단어, 이후 실시간
```

체감 속도는 동일하지만 **사용자가 기다린다는 느낌이 사라짐**.
