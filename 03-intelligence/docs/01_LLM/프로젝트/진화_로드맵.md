# 프로젝트 진화 로드맵 — 2023 → 2026

> 작성일: 2026-03-19
> 현재 위치: 2023 수준 (sLLM + RAG + LangChain Chain)
> 목표: 오버엔지니어링을 각오하고 최신 트렌드 적용

---

## 현재 위치 (2023 수준)

```
Loki API → ChromaDB → LangChain Chain → llama3.1:8b → 답변
```

- 질문하면 벡터검색 → 답변 (경로 고정)
- 사람이 직접 메뉴 선택 (xdr.sh)
- 모델이 시키는 것만 함

---

## 2024 수준으로 올리기

### ① 모델 스위치 — qwen2.5:14b (즉시 가능)

```
왜: llama3.1:8b 한국어 품질 한계
어떻게: .env 한 줄 변경
OLLAMA_MODEL=qwen2.5:14b
효과: 한국어 답변 품질 체감 상승
```

### ② 하이브리드 검색 — BM25 + 벡터 검색 병행

```
왜: 현재 벡터검색만 → "218.92.0.23" 같은 정확한 IP는 벡터검색에서 놓칠 수 있음
어떻게:
  pip install rank_bm25
  embedder.py 에 BM25 인덱스 추가
  검색 시 벡터점수 + BM25점수 합산 (RRF: Reciprocal Rank Fusion)
효과: 정확한 IP/포트/이벤트명 검색 정확도 향상
```

### ③ Agent 도입 — LangChain AgentExecutor

```
왜: 현재는 "질문 → 벡터검색 → 답변" 고정
    "보고서 만들고 공격 IP 조회해줘" 같은 복합 요청 불가
어떻게:
  rag_chain.py 에 @tool 데코레이터로 함수 등록
  chain → AgentExecutor 교체
  LLM이 tool_ssh_attacks(), tool_generate_report() 스스로 선택

효과:
  이전: 사용자가 xdr.sh 메뉴에서 1번, 2번 직접 선택
  이후: "어제 공격 정리하고 보고서 만들어줘" 한 마디로 처리
```

### ④ 스트리밍 응답

```
왜: 현재는 LLM이 전부 생성 완료 후 한번에 출력 → 느리게 느껴짐
어떻게:
  cli.py: chain.stream() 으로 교체
  app.py: st.write_stream() 으로 교체
효과: ChatGPT처럼 글자가 실시간으로 나오는 UX
```

## 2025 수준으로 올리기

### ⑤ LangGraph — 상태 기반 멀티스텝 워크플로우

```
왜: AgentExecutor는 단순 도구 호출만
    "공격 탐지 → 심각도 판단 → 심각하면 즉시 보고서 → 아니면 일간 보고서에 누적"
    같은 조건 분기 워크플로우 불가
어떻게:
  pip install langgraph
  노드: [분석] → [심각도 판단] → 분기 → [즉시알림] or [누적]
  엣지: 조건에 따라 다음 노드 선택

효과:
  이전: 단순 Q&A
  이후: 자동 보안 대응 워크플로우
```

```
실제 구현 예시:

  새 로그 감지
      │
      ▼
  [분석 노드] llama3.1:8b 로 위험도 판단
      │
      ├─ 심각/높음 → [즉시 알림 노드] → 터미널 경보 + 보고서 즉시 생성
      └─ 중간/낮음 → [누적 노드] → ChromaDB 저장 후 일간 보고서에 포함
```

### ⑥ MCP (Model Context Protocol) — Anthropic 2024 발표

```
왜: 현재 Tool 등록 방식은 이 프로젝트 전용
    MCP를 쓰면 Claude Desktop, Cursor, VSCode 등에서
    이 프로젝트의 Loki 쿼리 기능을 바로 사용 가능
어떻게:
  pip install mcp
  loki_client.py 함수들을 MCP 서버로 노출
  Claude Desktop에서 "@xdr SSH 공격 조회해줘" 로 바로 호출

효과:
  이전: xdr.sh 실행 → 메뉴 선택 → 결과 확인
  이후: Claude Desktop 채팅창에서 바로 질의
```

### ⑦ Multi-Agent — 역할 분담

```
왜: 하나의 LLM이 검색+분석+보고서까지 담당 → 품질 한계
어떻게 (CrewAI 또는 AutoGen):

  [수집 Agent]  → Loki에서 로그 수집 담당
      │
  [분석 Agent]  → 위험도 판단, 패턴 분석 담당
      │
  [보고 Agent]  → 보고서 작성, 요약 담당

효과: 각 Agent가 전문화 → 전체 품질 향상
```

## 2026 트렌드 — 현재 업계 방향

### ① Agentic AI 가 기본값

```
2024: "Agent 써볼까?"
2026: Agent 없는 LLM 앱은 레거시 취급

- 사용자가 목표만 말하면 Agent가 알아서 계획·실행·완료
- "보안 모니터링해줘" → 매일 자동 동기화, 이상 탐지, 보고서까지 자동
```

### ② 추론 모델 (Reasoning Model) 부상

```
OpenAI o3, DeepSeek-R1, QwQ 등
일반 LLM과 다른 점:
  일반 LLM: 질문 → 즉시 답변
  추론 모델: 질문 → 내부에서 수십 번 생각(Chain of Thought 자동화) → 답변

보안 분야 적용:
  복잡한 공격 패턴 분석에 추론 모델이 훨씬 정확
  "이 IP가 APT 공격인지 단순 스캔인지" 같은 판단
```

### ③ MCP 생태계 확장

```
2025: MCP 발표, 일부 도구 지원
2026: 대부분의 개발 도구가 MCP 지원
  - Cursor, VSCode, JetBrains → MCP 내장
  - GitHub, Slack, Notion → MCP 서버 공식 제공
  - 이 프로젝트 → MCP 서버 하나 만들면 모든 곳에서 접근 가능
```

### ④ 로컬 AI + 클라우드 하이브리드

```
단순 분류/라우팅: 로컬 sLLM (빠름, 무료)
복잡한 추론:     클라우드 LLM (Claude, GPT-4o)
비용 최적화:     작업 복잡도에 따라 자동 라우팅

이 프로젝트 적용 예:
  "로그 분류"      → nomic-embed-text 로컬 처리
  "단순 현황 질문" → llama3.1:8b 로컬 처리
  "APT 분석 요청" → Claude API 호출 (복잡한 추론)
```

### ⑤ AI Security Operations (AI SOC) 부상

```
이 프로젝트가 향하는 방향이 정확히 이것

2026 업계 트렌드:
  SIEM(Suricata/Wazuh) + sLLM + Agent = AI SOC 자동화
  - 이상 탐지 자동화
  - 위협 인텔리전스 자동 수집
  - 대응 플레이북 자동 실행
  - 보고서 자동 생성

현재 이 프로젝트는 AI SOC의 "분석 + 보고" 부분을 구현한 상태
```

## 이 프로젝트의 미래 아키텍처

```
현재 (2023):
  Loki → ChromaDB → Chain → llama3.1:8b → 답변

목표 (2026):
  Loki → ChromaDB
    │
  LangGraph 워크플로우
    ├─ [수집 Agent]   새 로그 자동 감지 및 동기화
    ├─ [분석 Agent]   위험도 판단 (sLLM 로컬)
    ├─ [추론 Agent]   복잡한 패턴 분석 (추론 모델 또는 Claude API)
    └─ [보고 Agent]   자동 보고서 생성 + 알림
    │
  MCP 서버
    └─ Claude Desktop / Cursor 에서 직접 접근
```
