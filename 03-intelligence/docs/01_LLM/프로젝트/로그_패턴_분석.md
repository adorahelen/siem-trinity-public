> 작성일: 2026-03-20
> 문서로 배울 수 없는 것 — 실제 로그를 보고 패턴을 읽는 감각

---

## 핵심 전제

```
로그 분석은 "읽는 것"이 아니라 "보는 것"

처음: 로그 한 줄 한 줄 해석
숙련: 수천 줄을 훑으며 이상한 것이 눈에 띔

이 감각은 반복 노출로만 형성됨
```

## 이 프로젝트의 주요 로그 패턴

### SSH 공격 패턴 (auth 로그)

```
[정상]:
  Accepted publickey for user from 100.x.x.x port 52341 ssh2

[단순 스캔]:
  Invalid user admin from 218.92.0.23 port 41234
  Invalid user root from 218.92.0.23 port 41235   ← 같은 IP, 포트 순차 증가
  Invalid user ubuntu from 218.92.0.23 port 41236  ← 사전 공격 패턴

[지속 공격]:
  같은 IP에서 수백 건/시간 → fail2ban 차단 직전 패턴
  새벽 2~4시 집중 → 자동화 봇 가능성
  포트 번호가 무작위 → 진짜 공격, 순차면 스캐너

[주목할 신호]:
  - 새로운 IP에서 처음 등장
  - 기존 차단 IP 해제 후 재시도
  - 존재하는 실제 계정명으로 시도 (내부 정보 탐색 가능성)
```

### Suricata 알림 패턴

```
[오탐 가능성 높음]:
  ET SCAN 류 → 스캐너가 많아 민감도 높음
  INFO 급 이벤트 → 정보성, 즉각 대응 불필요

[실제 위협 가능성]:
  alert_severity=1 (Critical) → 즉시 확인
  동일 IP에서 여러 rule_id 동시 발화 → 멀티벡터 공격
  내부 IP가 src → 내부 감염 또는 오설정

[패턴 읽기]:
  같은 rule_id가 다른 IP에서 동시 → 캠페인 공격
  야간에 갑자기 증가 → 자동화 공격
  특정 포트(445, 3389, 22) 집중 → 알려진 취약점 스캔
```

### Zeek 패턴

```
zeek_conn — 연결 패턴:
  conn_state="S0" → SYN만 보내고 응답 없음 → 포트 스캔
  conn_state="REJ" → 거부됨 → 차단 중이지만 시도는 계속
  duration 매우 짧음 + 반복 → 스캔 또는 봇

zeek_dns — DNS 패턴:
  rcode_name="NXDOMAIN" 폭발 → DGA(악성 도메인 생성) 가능성
  동일 IP에서 수백 개 다른 도메인 쿼리 → 악성코드 C2 탐색
  .onion, .bit 같은 비표준 TLD → 즉시 확인

zeek_notice — 이미 탐지된 것:
  note="Scan::Port_Scan" → 포트 스캔 확정
  note="SSH::Password_Guessing" → 비밀번호 추측 확정
```

## 패턴 감각을 키우는 방법

### 1. 베이스라인 파악

```
먼저 "정상"이 어떻게 생겼는지 알아야 이상을 감지

실행:
  python loki_client.py 로 평상시 데이터 주기적 확인
  "보통 하루에 SSH Invalid user가 몇 건이지?"
  "Suricata alert가 평균 몇 개?"

베이스라인 없이는 이상 탐지 불가
```

### 2. 연관 분석

```
단일 로그가 아닌 여러 소스를 교차 확인

예시:
  Suricata가 218.92.0.23 alert 발생
    → auth 로그에서 같은 IP SSH 시도 확인
    → zeek_conn에서 연결 패턴 확인
    → fail2ban이 차단했는지 확인

한 소스만 보면 놓치는 것을 교차 분석으로 발견
```

### 3. 시간축 분석

```
이벤트의 시간 순서가 중요

공격 킬체인 패턴:
  정찰 (스캔) → 취약점 탐색 → 침투 시도 → 횡이동

예시:
  02:00 zeek_conn SYN 스캔 시작
  02:05 Suricata 포트 스캔 감지
  02:10 auth SSH Invalid user 시작
  02:15 fail2ban Ban
  → 연속된 하나의 공격 흐름

시간 간격이 너무 규칙적 → 자동화 봇
시간 간격이 불규칙 → 사람이 직접 조작 가능성
```

## 자주 놓치는 패턴

```
1. 내부 IP의 이상 행동
   외부 IP에 집중하다 내부 192.168.x.x 이상 트래픽 무시
   → 내부 감염 또는 내부자 위협

2. 낮은 빈도 지속 공격 (Slow and Low)
   한 번에 폭발적이지 않고 하루에 1~2번씩 수주간 지속
   → 탐지 회피 목적

3. 알려진 정상 포트의 이상 트래픽
   443(HTTPS)으로 들어오는 C2 통신
   → 포트만 보고 정상으로 간주하는 실수
```
