# Attention 메커니즘

> 작성일: 2026-03-20
> Transformer의 핵심 — "무엇에 집중할 것인가"를 학습하는 메커니즘

---

## 핵심 직관

```
사람이 글을 읽을 때:
  "그 남자는 피곤했다. 그래서 [그]는 일찍 잠들었다"
  → "그"가 누구인지 파악하려면 앞 문장의 "남자"에 집중

Attention:
  모든 토큰 쌍의 관련성을 수치로 계산
  → 현재 토큰이 어떤 토큰에 얼마나 주목할지 결정
```

---

## Q, K, V — 쿼리, 키, 값

Attention의 3가지 핵심 행렬.

```
비유: 도서관 검색

Query (Q): 내가 찾으려는 것 ("파이썬 튜토리얼")
Key (K):   책의 제목/태그 ("파이썬", "프로그래밍", ...)
Value (V): 실제 책 내용

과정:
  내 Query와 각 책의 Key를 비교 → 유사도 점수
  점수가 높은 책의 Value를 더 많이 가져옴
```

---

## Attention 계산 과정

```
① 각 토큰을 Q, K, V 벡터로 변환
   (학습 가능한 가중치 행렬로 선형 변환)

② 모든 Q-K 쌍의 내적(dot product) 계산
   → 유사도 점수 행렬

③ Softmax로 점수를 확률로 변환
   → 모든 토큰에 대한 Attention 가중치 (합=1)

④ 가중치 × V → 가중 합산
   → 각 토큰의 새로운 표현 (문맥 반영됨)
```

## Self-Attention vs Cross-Attention

```
Self-Attention (자기 자신과):
  같은 시퀀스 내 토큰들끼리 Attention
  "나는 오늘 밥을 먹었다" → 각 단어가 서로를 참조
  → 인코더, 디코더 모두에서 사용

Cross-Attention (다른 시퀀스와):
  인코더 출력 ↔ 디코더 입력 간 Attention
  번역 시 원문 ↔ 번역문 연결
  → 인코더-디코더 구조에서 사용
```

## Causal Attention (Masked Attention)

```
GPT 계열 LLM (Decoder-only)의 핵심 제약

미래 토큰을 보지 못하도록 마스킹:
  "나는 오늘 밥을 [먹었다]"
  → "먹었다" 예측 시 "먹었다" 이후 토큰은 참조 불가

왜 필요한가:
  "다음 토큰 예측" 태스크에서
  정답(미래)을 미리 보면 학습이 의미 없음

추론 시:
  실제로 미래 토큰이 없음 → 자연스럽게 적용됨
```

## Multi-Head Attention

```
Attention을 여러 개 병렬로 수행

단일 Attention:
  하나의 관점에서만 관계 파악

Multi-Head:
  여러 관점을 동시에 파악
  헤드 1: 문법 (주어 ↔ 동사)
  헤드 2: 공참조 (대명사 ↔ 명사)
  헤드 3: 의미적 유사성
  ...

결과를 이어붙여(concatenate) 최종 표현

llama3.1:8b: 32개 헤드
```

## KV Cache — 추론 최적화

```
추론 시 문제:
  이미 처리한 토큰의 K, V를 매번 재계산 낭비

KV Cache:
  이미 계산한 K, V를 캐시에 저장
  새 토큰 추가 시 캐시에서 가져옴
  → 추론 속도 크게 향상

단점:
  긴 컨텍스트일수록 캐시 크기 증가 → 메모리 부담
  이것이 "컨텍스트 윈도우"가 메모리를 많이 잡아먹는 이유
```

## Attention이 RAG와 만나는 지점

```
RAG에서 검색된 로그 텍스트가 프롬프트에 포함될 때:

Attention이 하는 일:
  질문 토큰 ↔ 로그 텍스트 토큰 관련성 계산
  "어떤 IP가 공격했나?" → 로그의 IP 주소 부분에 높은 Attention
  → LLM이 관련 부분에 집중해 답변 생성

이것이 RAG + LLM이 효과적인 이유:
  단순히 텍스트를 붙여줬을 뿐인데
  Attention이 알아서 관련 부분을 찾아냄
```
