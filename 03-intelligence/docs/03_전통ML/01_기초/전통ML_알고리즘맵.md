# 전통 ML 알고리즘 전체 지도

> 작성일: 2026-03-20
> LLM 사이즈맵과 대응 — 전통 ML 알고리즘 전체 조망

---

## 전체 지도

```
전통 ML 알고리즘
├── 지도학습 (Supervised)
│   ├── 회귀 (Regression) — 연속값 예측
│   │   ├── 선형 회귀 (Linear Regression)
│   │   ├── 릿지 / 라쏘 (Ridge / Lasso)
│   │   └── 서포트 벡터 회귀 (SVR)
│   │
│   └── 분류 (Classification) — 클래스 예측
│       ├── 로지스틱 회귀 (Logistic Regression)
│       ├── 결정 트리 (Decision Tree)
│       ├── 랜덤 포레스트 (Random Forest)
│       ├── SVM (Support Vector Machine)
│       ├── KNN (K-Nearest Neighbors)
│       ├── 나이브 베이즈 (Naive Bayes)
│       └── XGBoost / LightGBM (그래디언트 부스팅)
│
├── 비지도학습 (Unsupervised)
│   ├── 군집화 (Clustering) — 그룹 찾기
│   │   ├── K-Means
│   │   ├── DBSCAN
│   │   └── 계층적 군집화
│   │
│   └── 차원 축소 (Dimensionality Reduction)
│       ├── PCA (주성분 분석)
│       └── t-SNE
│
└── 강화학습 (Reinforcement Learning)
    ├── Q-Learning
    └── PPO (게임 AI, 로봇 제어에 주로 사용)
```

## 알고리즘별 특징 요약

### 지도학습 — 회귀

| 알고리즘 | 핵심 아이디어 | 적합한 상황 |
|---------|------------|-----------|
| 선형 회귀 | 직선으로 관계 설명 | 피처와 결과가 선형 관계 |
| 릿지 / 라쏘 | 선형 회귀 + 과적합 방지 | 피처 수가 많을 때 |
| SVR | 허용 오차 범위 내 최적선 | 이상치에 강인해야 할 때 |

### 지도학습 — 분류

| 알고리즘 | 핵심 아이디어 | 적합한 상황 |
|---------|------------|-----------|
| 로지스틱 회귀 | 확률로 클래스 분류 | 빠른 기준선(baseline) 필요 |
| 결정 트리 | 조건 분기로 분류 | 해석 가능성이 중요할 때 |
| 랜덤 포레스트 | 결정 트리 수백 개 앙상블 | 범용, 안정적 성능 |
| SVM | 클래스 경계 최대화 | 고차원 데이터, 이진 분류 |
| KNN | 가장 가까운 K개 이웃 다수결 | 간단, 소규모 데이터 |
| 나이브 베이즈 | 조건부 확률 기반 | 텍스트 분류, 스팸 필터 |
| XGBoost | 오답을 순차 보정하는 앙상블 | 정형 데이터 최고 성능 |

### 비지도학습

| 알고리즘 | 핵심 아이디어 | 적합한 상황 |
|---------|------------|-----------|
| K-Means | K개 중심점 기준 군집 | 군집 수를 미리 알 때 |
| DBSCAN | 밀도 기반 군집 | 군집 수 모를 때, 이상치 탐지 |
| PCA | 분산이 큰 방향으로 차원 축소 | 시각화, 노이즈 제거 |

## LLM과 비교

```
전통 ML 알고리즘:
  - 수식/통계 기반
  - 입력: 사람이 선택한 숫자 피처
  - 출력: 클래스 or 수치 하나
  - 해석 가능 (결정 트리: 어떤 조건으로 분류했는지 추적 가능)

LLM:
  - 신경망 (Transformer) 기반
  - 입력: 텍스트 원문 (토큰화 후 내부 처리)
  - 출력: 자연어 (다음 토큰 확률)
  - 해석 불가 (블랙박스 — 왜 이 답을 했는지 내부 추적 어려움)
```

## 현업에서 아직 전통 ML이 쓰이는 이유

```
1. 해석 가능성 (Explainability)
   → 금융, 의료, 법률에서 "왜 이 결정을 했는가" 필요
   → 결정 트리, 로지스틱 회귀는 규칙이 명확

2. 빠른 추론 속도
   → GPU 없이 CPU만으로 밀리초 단위 예측
   → 실시간 처리가 필요한 보안 시스템, 결제 승인 등

3. 정형 데이터 성능
   → 숫자/범주형 테이블 데이터에서는 XGBoost가 LLM보다 뛰어난 경우 다수
   → Kaggle 정형 데이터 대회 1위는 여전히 XGBoost/LightGBM

4. 소규모 데이터
   → LLM 파인튜닝은 수만 건 필요
   → 전통 ML은 수백 건으로도 학습 가능
```
