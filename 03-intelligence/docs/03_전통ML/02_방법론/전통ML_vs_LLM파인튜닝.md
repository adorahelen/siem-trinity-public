# 전통 ML vs LLM 파인튜닝 — 훈련 방식 비교

> 작성일: 2026-03-20
> 핵심 발견: 역전파 원리는 동일, 파라미터 수 차이가 GPU 필요 여부를 결정

---

## 왜 둘 다 "훈련"인가

**훈련의 본질은 동일합니다:**

```
데이터 입력 → 예측 → 오차 계산 → 가중치(파라미터) 업데이트 → 반복
```

이 과정을 **역전파(Backpropagation)** 라고 하며,
전통 ML도 LLM도 이 원리를 사용합니다.

---

## 모델 구성 차이

```
전통 ML (랜덤포레스트 예시):
  파라미터 수: 수천 ~ 수백만
  구조:        결정 트리 여러 개 묶음
  입력:        숫자 피처 (IP, 포트, 패킷 수 등 사람이 직접 선택)
  출력:        클래스 (공격 / 오탐)

LLM (llama3.1:8b):
  파라미터 수: 8,000,000,000 (80억)
  구조:        Transformer (수백 개 레이어, 어텐션 헤드)
  입력:        토큰 (텍스트 전체를 숫자로 변환, 사람이 피처 선택 불필요)
  출력:        다음 토큰 확률분포
```

---

## GPU 사용량 비교

```
전통 ML 훈련 (sklearn 랜덤포레스트):
  GPU:  거의 불필요 (CPU만으로 충분)
  RAM:  수 GB
  시간: 수 분 ~ 수 시간
  비용: 노트북으로 가능

LLM 파인튜닝 (llama3.1:8b, LoRA):
  GPU VRAM: 최소 16GB ~ 48GB
  RAM:      32GB+
  시간:     수 시간 ~ 수 일
  비용:     고사양 GPU 필요 (RTX 3090급 이상)

LLM 파인튜닝 (Full Fine-tuning):
  GPU VRAM: 80GB+ (A100 급)
  시간:     수 일
  비용:     A100 80GB 기준 시간당 수만 원

LLM 사전학습 (처음부터):
  GPU:  H100 수천 장 클러스터
  시간: 수 개월
  비용: 수백억 원 (GPT-4 추정 ~$100M)
```

**GPU가 필요한 이유:** 파라미터가 80억 개이면 업데이트할 숫자도 80억 개.
행렬 연산을 병렬로 처리하지 않으면 현실적인 시간 안에 불가능.
CPU는 순차 연산, GPU는 수천 코어 병렬 연산 → 속도 차이 수백 배.

---

## 한 줄 요약 표

| | 전통 ML | LLM 파인튜닝 | LLM 사전학습 |
|--|---------|------------|------------|
| 훈련 원리 | 역전파 동일 | 역전파 동일 | 역전파 동일 |
| 모델 구조 | 트리 / SVM 등 | Transformer | Transformer |
| 파라미터 수 | 수백만 이하 | 수십억 (일부만 학습) | 수십억 (전체 학습) |
| GPU | 불필요 | 고사양 필요 | 수천 장 필요 |
| 데이터 규모 | 수천 건 | 수만 ~ 수백만 건 | 수조 토큰 |
| 데이터 형태 | 숫자 피처 (사람이 선택) | 텍스트 (토큰 자동 변환) | 텍스트 전체 |

---

## 왜 이 프로젝트에서 전통 ML을 안 쓰나

보안 로그에 전통 ML을 적용하려면:

```python
# 학습 데이터가 필요
학습데이터 = [
    {"src_ip": "218.92.0.23", "port": 22, "alert": "ET SCAN", "label": "실제공격"},
    {"src_ip": "192.168.1.5", "port": 80, "alert": "ET SCAN", "label": "오탐"},
    ...  # 수천 건 필요, 모두 사람이 레이블링
]
```

| 문제 | 이유 |
|------|------|
| 레이블(정답)이 없다 | 어느 alert가 진짜 공격인지 사람이 하나씩 판단해야 함 |
| 패턴이 계속 바뀐다 | 새 공격 기법마다 재훈련 필요 |
| 설명 생성 불가 | "이 IP는 공격" 만 출력, 이유 설명 없음 |

LLM(RAG)은 레이블 없이도, 재훈련 없이도, 한국어 설명과 함께 답변 가능.

---

## 이 프로젝트의 선택

```
전통 ML 훈련:  ❌ (레이블 데이터 없음, 패턴 가변)
LLM 파인튜닝:  ❌ (비용, 보안 로그 학습 데이터 구축 필요)
LLM 추론만:    ✅ (이미 학습된 llama3.1:8b 사용)
RAG:           ✅ (Loki 실시간 로그 → ChromaDB → 컨텍스트 주입)
```
