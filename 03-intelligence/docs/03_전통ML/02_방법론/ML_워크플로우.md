## 단계별 설명

### 1. 문제 정의

```
"무엇을 예측/분류할 것인가"를 명확히

예시:
  입력: Suricata alert 로그 (IP, 포트, 이벤트 유형)
  출력: 실제 공격(1) / 오탐(0)
  유형: 이진 분류 (지도학습)
  성공 기준: 정밀도 90% 이상
```

### 2. 데이터 수집

```
목표: 레이블 있는 데이터 확보

보안 예시:
  - Suricata alert 로그 5,000건
  - 보안 전문가가 각 alert에 "공격 / 오탐" 레이블 부착
  - 시간: 전문가 2명이 2주 작업 (가장 큰 병목)
```

### 3. 탐색적 데이터 분석 (EDA)

```
데이터를 이해하는 단계

확인 항목:
  - 클래스 불균형: 공격 100건, 오탐 4,900건 → 보정 필요
  - 결측값: 일부 포트 정보 누락 → 처리 방법 결정
  - 이상치: 포트 번호 -1 같은 오류값 존재?
  - 피처 간 상관관계: 서로 비슷한 피처 중복 제거
```

### 4. 데이터 전처리

```
결측값 처리:
  - 제거 (전체 행 삭제)
  - 평균/중앙값으로 채우기
  - 별도 "결측" 카테고리로 처리

클래스 불균형 처리:
  - 오버샘플링 (SMOTE: 소수 클래스 인공 생성)
  - 언더샘플링 (다수 클래스 일부 제거)
  - 가중치 조정 (모델이 소수 클래스에 더 집중)

스케일링:
  - 피처 값 범위 통일 (정규화 / 표준화)
```

### 5. 피처 엔지니어링

→ [피처엔지니어링.md] 참고

```
보안 로그 예시:
  원본: "2026-03-19 02:13 Invalid user admin from 218.92.0.23 port 41234"
  피처: hour=2, is_night=1, is_invalid=1, ip_country=CN, port=41234, ...
```

### 6. 모델 선택 및 훈련

```
시작점 (Baseline): 로지스틱 회귀 (단순, 빠름, 해석 가능)
     ↓ 성능 부족 시
중간 모델: 랜덤 포레스트 (안정적, 피처 중요도 제공)
     ↓ 최고 성능 필요 시
고성능 모델: XGBoost / LightGBM

훈련:
  train_data → 모델.fit() → 가중치 업데이트 반복
```

### 7. 모델 평가

```
단순 정확도만 보면 안 됨 — 클래스 불균형 때문

보안에서 중요한 지표:

  정밀도 (Precision):
    "공격이라고 예측한 것 중 실제 공격 비율"
    → 낮으면 오탐이 많음 (불필요한 경보)

  재현율 (Recall):
    "실제 공격 중 탐지한 비율"
    → 낮으면 실제 공격을 놓침 (미탐지)

  F1 Score: 정밀도와 재현율의 조화 평균

보안에서는 재현율 우선:
  "공격을 놓치는 것" > "오탐이 많은 것"
```

### 8. 하이퍼파라미터 튜닝

```
하이퍼파라미터: 사람이 설정하는 모델 설정값
  랜덤 포레스트: 트리 개수, 최대 깊이
  XGBoost: 학습률, 트리 개수, 정규화 강도

탐색 방법:
  Grid Search: 모든 조합 시도 (느리지만 확실)
  Random Search: 랜덤 샘플링 (빠름)
  Bayesian Optimization: 이전 결과를 반영한 지능적 탐색
```

### 9. 배포 (Serving)

```
방식 1 — 배치 처리:
  매 시간 쌓인 로그를 한 번에 예측 후 결과 저장

방식 2 — 실시간 API:
  로그 1건 → API 호출 → 즉시 예측 결과 반환
  (Flask / FastAPI로 모델 감싸기)
```

### 10. 모니터링 및 재훈련

```
문제: 시간이 지나면 실제 데이터 패턴이 훈련 데이터와 달라짐 (데이터 드리프트)

보안 예시:
  2024년 데이터로 훈련한 모델 → 2026년 새 공격 패턴 탐지 못함

대응:
  - 정기적으로 새 레이블 데이터 추가 → 재훈련
  - 모델 성능 지속 모니터링
  - 성능 저하 감지 시 자동 재훈련 트리거
```

## 전통 ML vs LLM+RAG 워크플로우 비교

| 단계 | 전통 ML | LLM + RAG |
|------|---------|----------|
| 데이터 준비 | 레이블링 필요 (수주~수개월) | 로그 수집만 (즉시) |
| 피처 엔지니어링 | 수동 설계 (핵심 작업) | 없음 |
| 모델 훈련 | 필요 (GPU or CPU) | 없음 (이미 훈련된 LLM 사용) |
| 새 패턴 대응 | 재훈련 필요 | 로그 동기화만 |
| 설명 생성 | 불가 (분류 결과만) | 가능 (자연어 설명) |
| 초기 구축 비용 | 높음 | 낮음 |
| 추론 속도 | 매우 빠름 (밀리초) | 느림 (수초) |
