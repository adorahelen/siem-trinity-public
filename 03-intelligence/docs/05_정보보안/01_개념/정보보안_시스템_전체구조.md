# 정보보안 시스템 — 전체 구조 순서도

---

## [단계 0] 인터넷 연결의 시작

```
전 세계 인터넷
      │
      │  ← 수십억 개의 IP가 서로 패킷을 주고받는 거대한 네트워크
      │
   ISP (KT, SKT, LGU+)
      │
      │  ← 공인 IP 1개 할당 (예: 203.0.113.45)
      │     공인 IP = 전 세계에서 유일한 주소
      │     이 순간부터 전 세계 누구든 이 IP로 패킷을 보낼 수 있음
      │
   [내 네트워크 진입점]
```

## [단계 1] 공유기 / NAT 계층

```
   [공인 IP: 203.0.113.45]
      │
   [공유기 / 라우터]
   ├── NAT (Network Address Translation) 수행
   │     └─ 공인 IP 1개를 여러 기기가 공유
   │
   ├── [PC:     192.168.0.10]  ← 사설 IP (외부에서 직접 접근 불가)
   ├── [노트북: 192.168.0.11]
   ├── [서버:   192.168.0.12]
   └── [스마트폰: 192.168.0.13]
```

**핵심:**
- 외부 → 내부 : 공유기가 막음 (포트포워딩 설정 없으면 차단)
- 내부 → 외부 : 자유롭게 나감 ← 악성코드가 이 방향을 악용

## [단계 2] 방화벽 (Firewall)

```
   인터넷 (공격자 포함)
      │
      │  SYN 패킷 도착
      ▼
   ┌─────────────────────────────────────┐
   │             방화벽                   │
   │                                     │
   │  검사 항목:                          │
   │  ① 출발지 IP가 블랙리스트인가?        │
   │  ② 목적지 포트가 허용 목록인가?       │
   │  ③ 인바운드/아웃바운드 정책 위반?     │
   │  ④ 연결 상태(ESTABLISHED/NEW)?       │
   └─────────────────────────────────────┘
      │                    │
   [허용]               [차단]
      │                    │
      ▼                    ▼
   내부 서버           패킷 DROP
                      (응답 없음)
```

**방화벽의 한계:**
포트 80(HTTP)이 열려있으면 → 내용물은 보지 않고 통과시킴
즉, 정상 포트를 통한 공격은 방화벽이 막지 못함 → IDS/IPS 필요

---

## [단계 3] DMZ 구조 (서버 운영 시)

```
   인터넷
      │
   [방화벽 외부]
      │
   ┌──────────────────────────────┐
   │  DMZ (비무장지대)             │
   │  ├── 웹서버  (포트 80/443)    │  ← 외부 공개 서버
   │  ├── 메일서버 (포트 25)       │
   │  └── DNS서버  (포트 53)       │
   └──────────────────────────────┘
      │
   [방화벽 내부]
      │
   ┌──────────────────────────────┐
   │  내부망 (인트라넷)            │
   │  ├── DB서버 (포트 5432)       │  ← 절대 외부 노출 금지
   │  ├── 내부 시스템              │
   │  └── 백업 서버               │
   └──────────────────────────────┘
```

**핵심 원칙:**
웹서버가 해킹되어도 → 내부 DB에는 직접 접근 불가
DMZ와 내부망 사이에도 방화벽이 존재

## [단계 4] IDS / IPS — 트래픽 내용 검사

```
   방화벽 통과한 트래픽
      │
      ▼
   ┌─────────────────────────────────────────┐
   │        IDS / IPS 엔진 (예: Suricata)    │
   │                                         │
   │  패킷 내용 분석:                         │
   │  ① 시그니처 탐지: 알려진 공격 패턴 비교  │
   │     예) SQL Injection: ' OR 1=1 --       │
   │     예) XSS: <script>alert()</script>   │
   │  ② 이상 탐지: 정상 트래픽과 다른 패턴   │
   │     예) 1초에 1000번 연결 시도           │
   │  ③ 프로토콜 위반: 규격 벗어난 패킷      │
   └─────────────────────────────────────────┘
         │                      │
      [IDS 모드]             [IPS 모드]
     탐지 + 알림만           탐지 + 즉시 차단
         │                      │
         ▼                      ▼
      로그 기록             패킷 차단 + 로그
      (SIEM 전송)           (SIEM 전송)
```

## [단계 5] WAF — 웹 전용 방어

```
   인터넷
      │
      ▼
   ┌──────────────────────────────────┐
   │  WAF (Web Application Firewall)  │
   │       예: ModSecurity            │
   │                                  │
   │  HTTP/HTTPS 요청 검사:           │
   │  ① SQL Injection 탐지           │
   │  ② XSS (크로스 사이트 스크립팅) │
   │  ③ CSRF 탐지                    │
   │  ④ 파일 업로드 공격             │
   │  ⑤ OWASP Top 10 룰셋 적용       │
   └──────────────────────────────────┘
      │
   [허용된 요청만]
      │
      ▼
   웹 애플리케이션 서버 (Nginx 등)
```

## [단계 6] VPN — 암호화 터널

```
   외부 사용자 (재택근무자 등)
      │
      │  평문 전송하면 중간에서 도청 가능 ← 공개 인터넷
      │
      ▼
   ┌────────────────────────────────┐
   │  VPN (Virtual Private Network) │
   │  예: Tailscale, WireGuard      │
   │                                │
   │  ① 양측에 VPN 클라이언트 설치  │
   │  ② 암호화된 터널 생성          │
   │  ③ 가상 사설 IP 부여           │
   │     예) 100.x.x.x (서버)   │
   │         100.x.x.x (맥북)   │
   └────────────────────────────────┘
      │
   [암호화된 터널 내부]
      │
   내부망과 동일한 접근 권한 획득
```

**XDR 시스템 적용:**
맥북 ──Tailscale VPN──▶ 서버 Loki(3100)
공개 인터넷에선 3100 포트 접근 불가, VPN 터널 안에서만 접근 가능

## [단계 7] SIEM — 통합 로그 분석

```
   각 보안 장비에서 로그 발생
   │
   ├── 방화벽 로그     (차단/허용 기록)
   ├── IDS 로그        (Suricata alert)
   ├── 웹서버 로그     (Nginx access)
   ├── WAF 로그        (ModSecurity rule)
   ├── OS 로그         (auth, syslog)
   ├── Zeek 로그       (conn, dns, ssl)
   └── Wazuh 로그      (보안 알림)
         │
         │  Promtail (로그 수집 에이전트)
         ▼
   ┌─────────────────────────────────┐
   │  Loki (로그 저장소)              │
   │  라벨 기반 인덱싱                │
   │  job="auth", job="suricata" 등  │
   └─────────────────────────────────┘
         │                  │
         ▼                  ▼
   Grafana (시각화)    XDR RAG (AI 분석)
   대시보드, 알림      자연어 질의 응답
```

## [단계 8] 공격 시나리오 — 전체 흐름으로 보기

```
공격자
  │
  │ 1. 포트 스캔 (nmap)
  ▼
[방화벽] ──닫힌 포트──▶ DROP (공격자에게 응답 없음)
  │
  │ 2. 열린 포트 22(SSH) 발견
  ▼
[방화벽] ──22번 허용──▶ 통과
  │
  │ 3. SSH 브루트포스 시작 (1초에 수백 번 시도)
  ▼
[IDS: Suricata] ──패턴 탐지──▶ alert 로그 생성
  │
  │ 4. fail2ban이 로그 감시
  ▼
[fail2ban] ──10회 실패──▶ 해당 IP 방화벽에 자동 등록 (Ban)
  │
  │ 5. 이후 해당 IP는
  ▼
[방화벽] ──블랙리스트──▶ 모든 패킷 DROP
  │
  │ 6. 전체 과정이 Loki에 기록됨
  ▼
[XDR RAG] ──"오늘 SSH 공격 분석해줘"──▶ AI가 통합 분석 + 보고서 생성
```

## 전체 보안 계층 요약

```
인터넷
  │
  ├─ [1계층] NAT/공유기     — 사설 IP로 직접 노출 차단
  ├─ [2계층] 방화벽          — IP/포트 기반 필터링
  ├─ [3계층] DMZ            — 공개 서버와 내부망 분리
  ├─ [4계층] IDS/IPS        — 트래픽 내용 분석 (Suricata)
  ├─ [5계층] WAF            — 웹 공격 전용 방어 (ModSecurity)
  ├─ [6계층] VPN            — 관리자 접근 암호화 (Tailscale)
  ├─ [7계층] SIEM           — 전체 로그 통합 (Loki+Grafana)
  └─ [8계층] AI 분석        — 이상 징후 자동 탐지 (XDR RAG)
```

각 계층은 독립적으로 동작하며, **하나가 뚫려도 다음 계층이 방어**
→ **심층 방어 (Defense in Depth)**
